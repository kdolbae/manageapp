# 집대리 — 범용 도메인 모델 & 데이터 시작 방식

> 2026-07-23 확정. [05](05_신규플랫폼_제안.md)·[07](07_집대리_플랫폼_전달모델.md) 상위.
> ※ 기획 단계.

---

# 1. 원칙 — "범용 코어 + 테넌트 구성"

나노마스터 전용 개념(박람회·주관사·주방/욕실·지출22종…)을 **코드에 박지 않는다.**
대신 **범용 개체**를 만들고, 나노마스터는 그것을 **설정(configuration)으로** 자기 방식대로 쓴다.

```
범용 코어 (모든 업체 공통, 코드로 고정)
   +
테넌트 구성 (업체마다 다름, 데이터로 설정)
   ├─ 기능 on/off (엔타이틀먼트)
   ├─ 분류/코드 마스터 (접수형태·경비항목·작업유형…을 업체가 편집)
   ├─ 파트너 유형·상품·작업단위 정의
   └─ (선택) 용어 라벨 커스터마이즈
```

> 현행 UFFICE가 실패한 지점이 정확히 이것: 접수형태 11종·지출 22종·주방/욕실을
> **HTML에 하드코딩**해서 다른 업체는 못 쓴다. 집대리는 전부 **테넌트 설정**으로 뺀다.

---

# 2. 나노마스터 개념 → 범용 개념 매핑 ★

| 나노마스터(현행) | 범용 개념(집대리) | 처리 |
|---|---|---|
| 박람회 | **캠페인 / 영업건** (유입경로) | 박람회는 캠페인의 한 **유형(preset)**. 안 쓰는 업체는 기능 OFF |
| 주관사 | **파트너(거래처)** — 유형: 주관사 | 협력사·공급사·소개처도 **같은 테이블** |
| 영업자 | **사용자 + 역할(영업담당)** | |
| 시공기사 | **작업자(Technician)** | |
| 아파트 | **현장(Site)** | |
| 주방 / 욕실 | **작업단위(Task) — 테넌트가 정의** | 청소업체=거실/주방/화장실, 줄눈업체=욕실별… |
| 접수형태 11종 | **계약 분류** (테넌트 편집) | |
| 시공종류 | **작업 유형** (테넌트 편집) | |
| 지출내역 22종 | **경비 카테고리** (테넌트 편집) | |
| 상품(코팅 패키지) | **상품/서비스 카탈로그** | |
| 지점 | **테넌트 내 조직/브랜치** | |

→ **요청하신 데이터는 전부 그대로 들어간다.** 다만 "박람회"라는 이름으로 박히는 게 아니라
   "캠페인(=박람회)"으로 **구성된 상태**로 들어간다. 다른 업체는 같은 자리를 다르게 구성.

---

# 3. 파트너(거래처) 일반화 — 주관사 관리 대체

```
Partner (거래처)
  tenantId, name, bizNo?
  type: 주관사 | 협력사 | 공급사 | 소개처 | 기타   ← 테넌트가 유형 편집
  contacts[], accounts[], memo
  링크: Campaign, Expense, Contract 등에 참조
```
- 나노마스터의 주관사 41개 = `type=주관사` 인 Partner.
- 다른 업체는 하청·자재공급사·소개처를 같은 화면에서 관리.

---

# 4. 캠페인/영업 일반화 — 박람회 관리 대체

```
Campaign (영업건/캠페인)
  tenantId, name
  channel: 박람회 | 사전행사 | 온라인 | 소개 | 직접영업 | 기타  ← 편집
  siteId? (현장 연결)          organizerPartnerId? (주관사)
  rounds[] (차수),  schedules[] (일정: 홍보/설치/행사…)
  costs[] (박람회비 등 → Expense 연결)
  members[] (참여 영업담당)
  externalLinks[] (네이버카페·밴드 URL)
```
- 나노마스터 박람회 = `channel=박람회` 인 Campaign. 차수·일정·주관사·비용·카페/밴드 전부 계승.
- **박람회를 안 하는 업체**: Campaign 기능 OFF. 그래도 계약마다 `유입경로` 한 칸은 남길 수 있음.
- 박람회별 손익 통계(§04)는 Campaign 단위 집계로 범용화 → 어떤 채널이든 손익 산출.

# 5. 설정 가능한 분류(코드 마스터) — 하드코딩 금지 ★

현행이 HTML에 박은 목록들을 **테넌트별 편집 가능 리스트**로:

| 분류 | 나노마스터 기본값(seed) | 다른 업체 |
|---|---|---|
| 계약 분류(접수형태) | 음성계약·박람회·옵션·사전계약… | 각자 정의 |
| 작업 유형(시공종류) | 시공·AS·하자보수·미시공 | 각자 정의 |
| 작업 단위 | 주방·욕실 | 거실·화장실·현관… |
| 경비 카테고리 | 박람회비·인건비·교통비…(22종) | 각자 정의 |
| 상품/서비스 | 코팅 패키지들 | 각자 카탈로그 |
| 파트너 유형 | 주관사… | 하청·공급사… |
| 시공상태 | 미정·예정·배정·완료… | 각자 상태 흐름 |

- 신규 테넌트 개설 시 **기본 세트를 seed**로 깔아주고, 업체가 편집.
- 나노마스터는 현행 값들을 seed로 그대로 받음.

# 7. 데이터 시작 방식 — 확정 ★

사용자 결정: **과거 통째 이관 안 함. 필요한 마스터만 엑셀로 올리고, 거래는 새로 축적.**

| 데이터 | 방식 | 이유 |
|---|---|---|
| 현장(아파트) 1,050 | **엑셀 임포트** | 계속 재사용하는 마스터 |
| 상품/서비스 | **엑셀 임포트 or 재등록** | 카탈로그 |
| 작업자(기사) 45 | **엑셀 임포트** | 배정에 필요 |
| 사용자 79 | **엑셀 임포트 or 신규** | 계정 |
| 주관사/파트너 41 | **엑셀 임포트** | 소량 |
| 계약자 21,600 | **선택** — 재방문/AS 조회 원하면 임포트 | 판단 |
| 계약·입금·경비·시공 (거래) | **신규 축적** (이관 안 함) | 앞으로 쌓음 |
| 과거 통계 | 필요 시 현행 엑셀 다운으로 참고 | 이관 대상 아님 |

→ **대규모 MSSQL 마이그레이션 불필요.** 엑셀 임포터 몇 개만 만들면 됨 → 개발 대폭 단축·리스크 감소.
→ 과거 데이터는 현행 시스템/엑셀에 남아 있으니 조회는 그쪽으로.

# 8. 범용 메뉴 구조 (제안)

현행 나노마스터 메뉴 → 범용 재구성. 각 메뉴 = **기능 key(엔타이틀먼트)**.

| 범용 메뉴 | 대응(현행) | 기능 key |
|---|---|---|
| 계약 | 계약관리 | `contracts` |
| 고객 | 계약자관리 | `customers` |
| 현장 | 아파트관리 | `sites` |
| 작업/시공 | 시공관리 | `workorders` |
| 일정 | 일정관리 | `schedule` |
| 수납·결제 | 결제내역/수납 | `payments` |
| 경비 | 경비지출 | `expenses` |
| 파트너 | 주관사관리 | `partners` |
| 캠페인 | 박람회관리 | `campaigns` (옵션) |
| 상담 | 상담관리 | `consultations` |
| 메시지 | 문자/알림톡 | `messaging` |
| 분석 | 통계정보 | `analytics` |
| 설정 | 각종 설정 | `settings` (분류·상품·작업자·사용자·기능) |
| (공개) 소개 | — (신규) | `microsite` |

- 나노마스터: 전 기능 ON.
- 박람회 안 하는 업체: `campaigns` OFF → 메뉴·로직 통째 사라짐.

---

# 9. 범용화의 대가 (알아둘 것)
- 범용 = **테넌트가 처음에 설정을 해야 함** (분류·상품·작업단위 등).
- 나노마스터는 seed로 자동 세팅되니 부담 없음.
- 신규 업체 온보딩 시 "설정 마법사"로 완화 (M3).
- 트레이드오프: 살짝 더 유연 ↔ 살짝 더 설정. 다업체 판매엔 필수.
