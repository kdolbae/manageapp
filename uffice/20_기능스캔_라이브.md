## 1. 계약관리 `/sub/01/`

**목록 상단 집계**: 총 건수 · 시공완료 건수 · 취소 건수 · 매출취소총액(공급가) · 환불금액(공급가, 카드/현금 분리 표기)

**검색 필터**:
- 날짜 기준 선택: 계약일 / 시공완료일 / 시공예정일 / 취소일 + 기간(시작~끝)
- 아파트명 · 동호수 · 계약자명 · 계약자 전화번호
- 정렬: 계약일순 / 아파트명순 / 등록순 / 시공완료일 / 주방시공예정일 / 욕실시공예정일
- 버튼형 필터: 추가옵션 · 시공상태 · 접수형태 · 시공종류
- 잔액: 있음 / 없음
- 기사선택(드롭다운) · 작성자선택(드롭다운) · 시공기사 시공상태(완료/일부미시공/시공취소/시공연기)
- 지점선택

**액션**: 엑셀다운로드(`/bbs/liti_excel_220729.asp`) · 계약등록(`/sub/01/Default.asp?act=write`)

**목록 컬럼**: 번호 · 지점 · 접수형태(음성계/무상시 등) · 시공상태(배정/예정/미정 등 색상표기) · 계약일 · 계약자(승인여부) · 연락처 · (금액/시공/기사/작성자 등 우측 컬럼) · 카카오톡 버튼

**시공상태 값**: 배정 · 예정 · 미정 (색상 구분)
**접수형태 값**: 음성계 · 무상시 (등)

### 1-1. 계약등록 폼 (`/sub/01/Default.asp?act=write`) — "계약정보 등록" 1단계
> 1단계는 **계약자 기본정보만** 입력. 시공 단품·금액·결제는 저장 후 상세페이지에서 추가하는 구조로 추정.

| 필드 | 필수 | 비고 |
|---|---|---|
| 고객명 | ✔ | **등록 후 수정 불가** (불변 처리) |
| 고객 연락처1 | ✔ | 3분할 입력 |
| 고객 연락처2 | | 3분할 입력 |
| 계약담당 | ✔ | 담당 매니저 |
| 현장 / 동 / 호 / 타입 | ✔(현장·동·호) | 현장=아파트, 타입=평형 |
| 계약일 | ✔ | 초기화 버튼 |
| 입주예정일 | | 초기화 버튼 |
| 계약승인 | | 승인대기 / 승인 / 미승인 (라디오) |
| 세금계산서 | | 미발행 / 발행 + 발행번호 입력 |
| 현금영수증 | | 미발행 / 발행 + 전화번호 입력 |
| 기타사항 | | 자유 메모 |

액션: 확인 / 취소

### 1-2. 계약 상세 (`/sub/02/Default.asp?seq={계약번호}`) — ⭐도메인 모델 핵심
> 목록에서 행 클릭 → `/sub/02/`로 이동. `seq`가 계약 식별자.
> **상단 탭**: 계약정보 · 계약자 · 시공관리 · 상담내역

**① 기본정보**: 고객명 · 전화번호 · 이메일 · 계약일 · 계약담당 · 현장(아파트+동+호+타입) · 입주예정일 · 세금계산서(발행여부) · 현금영수증(발행여부) · 계약승인 · 박람회(연결) · 기타사항

**② 시공정보(요약)**: 지점 · 구분(예: `나노코팅(음성계약)`) · 시공종류 · 추가옵션 · 시공상태 · **시공예정일(주방/욕실 별도)** · **시공담당(주방/욕실 별도)** · 계약시공(시공내역 서술) · 무료시공품목 · 모바일웹(나의 메모, 주방/욕실) · 기사전달사항 · 상담내역 · 비고

**③ 계약금액 원장(요약 라인)** — 문서 설계원칙의 ledger가 실제로 구현됨:
```
계약금액 = 시공금액 − 할인금액 − 상품권
그리고: 매출취소총액 · 실계약금 · 입금 · 환불 · 남은금액(=계산값)
```

**④ 상세시공(단품 라인아이템 테이블)** — 한 계약에 단품 여러 개:
| 번호 | 지점 | 구분 | 계약시공 | 무료시공품목 | 시공예정일(주방/욕실) | 시공기사(주방/욕실) | 모바일웹(나의 메모) | 비고 | 관리 |
→ 하단 **[시공등록]** 버튼으로 단품 추가

**⑤ 시공별 계약금액(단품별 원장)**:
| 선택 | 구분 | 계약금액(VAT포함) | 매출취소총액 | 실계약금액 | 입금금액 | 환불금액 | 남은금액 |

**⑥ 입금(결제 이벤트 테이블)**:
| 입금일 | 구분 | 항목(계약금/잔금 등) | 결제수단(카드/계좌이체/현금) | 입금액 | 입금자명 | 승인번호 | 카드명/은행명 | 카드번호 | 영수증 | 비고 | 관리(수정/삭제) |

**⑦ 시공후기 테이블**:
| 번호 | 지점 | 시공사진등록일 | 후기등록일 | 계약자 | 아파트명 | 시공예정일 | 시공완료일 | 작성자 | 시공담당 | 시공완료메모 |

**하단 액션**: 목록

> 💡 **재설계 시사점**: 기존 문서의 "금액은 원장으로/단품 다건/주방·욕실 분리 일정" 설계가 실제 운영에서 그대로 확인됨. 입금은 append-only 이벤트, 잔액은 계산값. 주방/욕실이 **시공 축(2분할)** 으로 하드코딩돼 있음 → 신규는 범용 단품축으로 일반화 필요.

## 13. 종합 — 도메인 모델 & 재설계 함의

### 확인된 핵심 엔티티(레거시 실물)
- **테넌트/지점(branch)**: 약 9개(본사·호텔감성·대구·충청지사·나노폴 + 대행사 그리드웍스 등). 모든 목록이 `지점선택`으로 필터 → 멀티테넌시가 지점 단위.
- **고객 마스터(계약자)** ↔ **계약(seq)** 1:N. 계약자 실명은 등록 후 불변.
- **계약** = 기본정보 + 시공정보 + **단품(상세시공) N건** + 단품별 원장 + **입금 이벤트 N건** + 후기.
- **원장(ledger)**: 시공금액 − 할인 − 상품권 = 계약금액; 매출취소·입금·환불 이벤트, 남은금액=계산값. (append-only, soft-delete)
- **기사(engineer)** 마스터 + 월간 일정/캐파, 기사별 정산(주방/욕실 분리 시공비).
- **상품 카탈로그**: 패키지 / 추가시공품목, 지점별 노출.
- **박람회(expo)** + **주관사(organizer)** + **아파트(현장)** 3자 연결 → 획득 채널. 박람회별 P&L.
- **ERP**: 경비지출(부서·승인워크플로·부가세·영수증), 영업자·박람회·기사·월별 통계.
- **상담(consult)** 이력 게시판(취소방어·AS·인터넷가입 교차판매).
- **부가 서비스 연동**: 문자(자체)·이메일(타손)·카드PG(페이조아)·카카오톡·네이버지도.

### 하드코딩 → 범용화 필요 지점

3. **석재등급(인조대리석/엔지니어드스톤)** 등 업종 특화 속성 → 상품 속성 스키마로.
