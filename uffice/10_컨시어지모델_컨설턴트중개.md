# 집대리 — 컨시어지 모델 (컨설턴트 중개)

> 2026-07-23 전략 논의. [09](09_제품전략_양면플랫폼.md) 상위.
> ※ 기획/전략. 내 관점 포함.

---

# 1. 모델 정의 — 매니저가 중개하는 컨시어지 마켓플레이스

```
소비자 ──(단일 접점)── 담당 매니저(컨설턴트) ──(뒤에서)── 여러 협력업체
```
- 소비자는 **한 사람(담당 매니저)하고만** 소통.
- 매니저가 청소·줄눈·코팅 등 **여러 단품을 가로질러** 예산·순서·일정·에누리를 다 매니징.
- 협력업체는 계약 받아 시공·해피콜. 매니저가 그 사이 조율.
- 이게 "집대리(집 관리 대리인)" 개념을 **문자 그대로** 구현.

→ 순수 SaaS가 아니라 **관리형 서비스 + 소프트웨어**. 경제구조가 다르지만(사람이 낌) 신뢰·전환율·방어력이 훨씬 높다.

---

# 2. 왜 이 모델이 강한가

| 이유 | 설명 |
|---|---|
| **콜드스타트 완화** | 순수 양면 셀프서비스는 신뢰·조율이 어려움. 사람이 끼면 소비자 리스크가 사라짐 |
| **한국 정서** | 고관여·불안 구매(입주)일수록 "사람이 다 해준다"가 먹힘 |
| **선례 있음** | **집닥**(소비자↔인테리어업체 사이 "집닥맨" 중개 + 안전결제), 숨고(전문가 매칭). 집대리는 이를 **입주 단품(청소/줄눈/코팅)** 니치에 특화 |
| **조율 가치** | 입주 = 5개 업체 조율의 고통. 한 명이 다 해주면 그 자체가 상품 |

> 집대리 = **"인테리어 아닌 입주 단품 버전의 집닥"** 으로 포지셔닝 가능.

---

# 3. "에누리 요청하기" — 메커니즘 & 진짜 절약 ★

## 3.1 왜 이 표현이 좋은가
- "견적 요청"(거래적)·"상담 신청"(영업압박 느낌) 대신 **"에누리(깎아드려요)"** = 재밌고 소비자 편.
- 에누리 문화 = 소비자가 **이득 본다는 느낌**. 진입 문턱이 사라짐.
- 커밋이 아니라 **"얼마까지 되나 물어보는"** 가벼운 시작 → 자연스레 채팅·컨설팅으로.

## 3.2 이게 gimmick이 아닌 이유 — 번들 레버리지
```
매니저가 청소+줄눈+코팅을 묶어서 협력업체에 협상
  → 혼자 간 소비자는 못 받는 다품목 할인을 끌어냄
  → 소비자: 진짜 더 싸다   협력업체: 더 큰 번들 계약   플랫폼: 수수료
```
- **소비자가 직접 가는 것보다 실제로 저렴** → "에누리"가 립서비스가 아니라 진짜.
- Win-Win-Win이 성립하는 핵심 지점.

## 3.3 CTA 메커니즘
```
소비자: 단품 선택 → [에누리 요청하기] 탭
  → 담당 매니저와 채팅 열림 (+ "원하시면 언제든 통화")
  → 매니저가 뒤에서 협력업체들과 조율 → 번들 딜 제시
  → 계약 진행 → 협력업체가 시공/해피콜, 매니저가 총괄
```

---

# 4. 수수료 모델 — (a) vs (b)

사용자가 던진 두 안:

| 안 | 방식 | 평가 |
|---|---|---|
| (a) 명시적 컨설팅비 | 단품마다 가격 비례 3~5만원, **소비자 부담** | 투명·확장적이나 **한국은 컨설팅비 지불 정서 약함** → 저항 |
| (b) **업체 비용에 녹임** | 소비자엔 "무료 컨시어지", 협력업체가 수수료 부담 | **추천.** 소비자 저항 0, 사실상 마켓플레이스 take-rate |

## 4.1 추천: (b) — 단, 내부적으론 구조화해서 추적
- 소비자에겐 **무료 담당 매니저**로 포지셔닝.
- 협력업체가 **건당/단품당 수수료**(3~5만원 밴드, 가격 비례)를 플랫폼에 지불.
- 표시만 다를 뿐 **컨설팅비 = 커미션 = take-rate** 동일. 내부 원장엔 단품별 라인으로 정확히 기록.
- 나중에 시장이 성숙하면 명시적 노출로 전환 가능하게 설계.

## 4.2 협력업체가 왜 기꺼이 내나 ★
```
현행: 박람회비 = 박람회당 170만~520만원 선지출
집대리: 관리형 리드 = 건당 3~5만원
```
→ **박람회비의 수십분의 일**. 게다가 정제·번들된 고전환 리드.
   협력업체 입장에선 **훨씬 싼 고객획득 채널** → 저항 낮음.

# 5. 아키텍처 함의 — 플랫폼 레이어가 생긴다 ★★

컨설턴트가 **여러 협력업체(테넌트)를 가로질러** 조율하므로, 테넌트 위에 **플랫폼 레이어**가 필요.

```
[플랫폼 레이어] 집대리 소유
  소비자 계정 · 입주 플랜 · 에누리 요청 · 담당 매니저(컨설턴트)
  · 매칭 · 후기 집계 · 마케팅 연동
        │  리드 ↓        수수료 ↑
[테넌트 레이어] 각 협력업체 소유
  계약관리 · 시공관리 · 경비 · ERP (자기 워크스페이스)
```
- **리드 흐름**: 플랫폼 → 협력업체 (매칭된 리드가 그 업체 워크스페이스에 **계약 초안**으로 꽂힘)
- **수수료 흐름**: 협력업체 → 플랫폼
- 소비자 관계·매니저·매칭은 **플랫폼 소속** (특정 업체 소속 아님)
- → [07]의 멀티테넌시 위에 **플랫폼 공용 레이어**를 얹는 구조로 확정.

## 5.1 역할(Role) 추가
- **Consultant/Manager (담당 매니저)** = 플랫폼 레벨 역할.
- 한 소비자 입주 플랜 → 매니저 1명 배정.
- 매니저 전용 뷰: 그 소비자의 **모든 단품을 한 화면에서** (업체 넘나드는 통합 뷰).

---

# 6. 철칙 — 소비자는 매니저 1명하고만 ★

```
협력업체가 소비자에게 직접 콜드콜/스팸 ❌
모든 소통은 매니저 경유. (해피콜도 매니저가 조율)
```
- 이게 **전체 가치의 핵심**: 5개 업체에 시달리지 않는 것.
- 협력업체 해피콜은 매니저를 통하거나, 매니저 승인 하에.
- 어기면 컨시어지 가치가 무너짐 → 시스템·정책으로 강제.

---

# 7. 컨설턴트 운영 — 정직한 현실

| 항목 | 내용 |
|---|---|
| 확장 병목 | 사람이 낌 → 무한 확장 안 됨. 볼륨 늘면 컨설턴트 팀 필요 |
| 초기 해법 | **나노마스터 기존 인력**이 이미 상담·해피콜 함 → 초기 매니저로 전환, 추가 채용 0 |
| 품질=브랜드 | 매니저 1명이 브랜드. 나쁜 매니저 = 이탈 → **도구로 효율·품질 지원**(통합뷰·템플릿·스니펫) |
| 비용구조 | SaaS 마진 + 관리형 인건비 혼합. 수수료가 인건비를 커버하도록 단가 설계 |

---

# 8. 종합 — 수정된 그림
```
소비자 [무료]
  단품 선택 → "에누리 요청" → 담당 매니저(1명)
       매니저가 번들 협상(진짜 할인) · 순서 · 일정 총괄
            ↓ 리드            ↑ 수수료(업체 부담, 3~5만/단품)
협력업체 [계약/시공 무료 + ERP 유료]
  매칭 리드 = 박람회비보다 훨씬 싼 고객획득
```
- 소비자: 공짜 집사, 진짜 할인, 단일 창구.
- 협력업체: 싼 리드 + 운영도구.
- 플랫폼: 수수료(=컨설팅비 녹임) + ERP 부가 + 결제/마케팅.
