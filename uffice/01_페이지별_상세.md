# 1. 시공 등록/수정 폼 — `/sub/02/Default.asp?act=sigongedit&idx={sigongIdx}&seq={seq}`

시스템에서 **가장 복잡한 화면**. 시공 1건의 모든 필드 + 기사배정 + 시공비 정산이 한 폼에 있음.

## 1.1 폼 골격

```html
<form name="con_form" id="con_form" method="post"
      action="/sub/02/Default.asp" target="procfrm">   <!-- 숨김 iframe 제출 -->
```

| hidden | 값/용도 |
|---|---|
| `act` | `sigongeditproc` (등록 시 `sigongwriteproc` 추정) |
| `redir` | 처리 후 이동할 URL (검색조건 포함) |
| `idx` | 시공 PK |
| `SEQ` | 계약 PK |
| `pagesize` | 25 |
| `Content` | "다음에디터 사용시 크롬/FF/오페라 오류 제거를 위한 장치" (주석 원문) |
| `COM_NUM_chk` | 미사용으로 보임 |
| `items` / `itemsprice_k` / `itemsprice_b` / `gifts` | JS가 submit 직전 채우는 직렬화 배열 |

- 제출 방식: **hidden iframe(`procfrm`) 타겟 POST**. 페이지 이동 없이 처리되고 서버가 `redir`로 보냄.
- 추가 JS: `/js/vItemsV11.js` (이 페이지만 로드)

## 1.2 구분 분기 — `.nanoOnly` / `.ngOnly`

```
gubun1 = 인테리어(라벨: 나노코팅) | 홈케어
```
- `인테리어` → `.nanoOnly` 표시, `.ngOnly` 필드 전부 값비우고 `disabled`
- `홈케어` → 반대

**단, 홈케어 라디오(`#gubun1_2`)와 홈케어 종류(gubun3) UI는 전부 HTML 주석 처리됨.**
→ `.ngOnly` 분기는 도달 불가능한 죽은 코드. 초기화 스크립트도 `if('인테리어'=='인테리어')` 로 항상 참.

홈케어 종류(주석 상태 보존): 입주청소 · 베란다칠 · 새집증후군 · 음식물처리기 · 단열필름 · 인덕션 · 인터넷TV설치 · 시스템에어컨 · 기타

## 1.3 시공비 계산 로직 ★

`grade2` (라벨 "상판선택")가 계산 방식을 결정:

| grade2 | 표시 영역 | 주방시공비 공식 |
|---|---|---|
| `주방나노` | `.kitchen_nano` `.costpergisa` | `(con_supply_k / 1.1) × (gisa_bath_ratio_k × 0.01) + add_pay3` |
| `주방UV` | `.kitchen_uv` `.costpergisa` | `gisa_kitchen_unit_price + add_pay3` |
| `상품별시공비` | `.costperitem` | `sumcost_k + add_pay3` |

욕실시공비 (`gisa_bath_pay`):
| 조건 | 공식 |
|---|---|
| `grade2 == 주방UV` 또는 `주방나노` | `(con_supply / 1.1) × (gisa_bath_ratio × 0.01) + add_pay2` |
| `grade2 == 상품별시공비` | `sumcost_b + add_pay2` |

- `/1.1` = 부가세 제외 (공급가 소비자 → 세전)
- `add_pay2`(욕실) / `add_pay3`(주방) 라벨은 **"교통비"** 인데 주석·안내문구는 "추가금"으로 혼용
- `pre_tax_supply` / `pre_tax_supply_k` 는 readonly 계산 결과 표시용
- `gisa_bath_ratio`(욕실 %), `gisa_bath_ratio_k`(주방 %) 는 **기사 마스터에서 자동 주입** (readonly)
- 승인 체크박스: `gisak_payyn` (주방시공비승인), `gisab_payyn` (욕실시공비승인) — 값 `Y`

### 계약금액 계산 (`#amtDetails` 체크 시)
```
pre_amt(계약금액) = amt_etc(시공금액) − discount1(할인금액) − discount2(상품권)
```

## 1.9 이 페이지의 문제점

| # | 심각도 | 내용 |
|---|---|---|
| A1 | 높음 | **ASP가 JS 리터럴에 값을 그대로 삽입**: `if('인테리어'=='인테리어')`, `if('미정'=='시공완료')`, `if(''=='기타')`, `if(''=='')`. 값에 작은따옴표가 들어가면 스크립트 전체가 깨지고, XSS 경로가 됨 |
| A2 | 높음 | 욕실시공비 계산 조건이 `grade2=="주방UV" \|\| "주방나노"` — **주방** 값으로 욕실 공식을 고름. 조합에 따라 욕실 시공비가 갱신되지 않을 수 있음 |
| A3 | 중간 | `consolg.log(a)` 오타 (dailyLimit error 핸들러). 에러 시 또 에러 나서 원인 파악 불가 |
| A4 | 중간 | `.add_item2` / `.add_item3` 핸들러가 `$(document).ready` **밖**, 테이블 중간 `<script>`에서 바인딩 |
| A5 | 중간 | `.copy_date_kitchen` 이 `.attr('checked', true)` 사용 — jQuery 1.8.1이라 동작하지만 위험 |
| A6 | 낮음 | `gift_depth1` / `getGifts()` / `#gift1~3` 서비스 선택 로직이 통째로 남아있으나 **대응 UI 없음** (죽은 코드, 동일 핸들러가 주석본+실사용본 2벌) |
| A7 | 낮음 | 구버전 `.add_item`(대/중/소분류 + 수량) 로직 주석으로 잔존. `vItemDepth2_*Arr` 등 `/js/vItemsV11.js` 의존 |
| A8 | 낮음 | `SigongFinishedDAte` 오타가 name/id에 고정 |
| A9 | 낮음 | 지점 select가 hidden으로 대체됨(`<input type=hidden name=agency>`) — 지점 변경 UI 없는데 `changeAgency()`/`#agency` change 핸들러는 살아있음 |
| A10 | 낮음 | `sendit()` 의 필수값 검증이 대부분 주석 처리 — 실제 검증은 시공완료일/취소사유/취소일/계약시공/계약금액/이관지점만 |

# 2. 일정관리(기사일정) — `/sub/36/Default.asp?act=calendar`

> **주신 3번째와 4번째 HTML은 완전히 동일합니다.** 날짜(`.scheduleArea`)를 클릭하면
> 페이지 이동 없이 `ajax_gisa_schedule_summary_list.asp` 결과가 우측 `.calR` div에 주입되는 구조라
> 문서 소스 자체는 변하지 않습니다. 상세 내역을 문서로 남기려면
> **개발자도구 Network 탭에서 그 AJAX 응답 본문**을 떠 주셔야 합니다.

## 2.1 URL / 파라미터
```
/sub/36/Default.asp?act=calendar&today=YYYY-MM-DD&cDate=&sector=&agency=&...
```
- `today` — 표시 기준월. 이전/다음 달 링크가 `today` 를 ±1개월 (일자는 유지)
- `agency` (지점), `gisa` (기사) 필터 → `document.schfrm.submit()`
- 폼 hidden: `cDate`, `act`, `today`, `sigongExpDate`

## 2.2 화면 구성
```
좌측 40%  : 월 달력 (.cal)
우측 57%  : 선택일 상세 (.calR) — position:fixed, AJAX로 채워짐
```

달력 셀 1개의 구조:
```html
<span class="date">일</span>
<span class="txt">
  <ul class="memoArea">          <!-- 날짜별 메모, 인라인 편집 -->
    <li class="outputArea">      <!-- 표시 -->
    <li class="inputArea">       <!-- textarea, 기본 display:none -->
  </ul>
  <ul><li class="txtY">휴무 : 기사명, 기사명</li></ul>
  <ul class="scheduleArea" onclick="schedule_summary_list('YYYY-MM-DD','')">
    <li class="btn-txt">기사명 : N건</li>
  </ul>
</span>
```
- 오늘 날짜 셀: `bgcolor=ffefeb`
- 메모 영역 배경: `#b5daf6`

## 2.3 AJAX

| URL | 트리거 | 파라미터 | 결과 |
|---|---|---|---|
| `/ajax/ajax_setSchMemos.asp` | 메모 blur / 750ms 디바운스 | `AGENCY`, `YYMM`, `DD`, `Contents` | 날짜별 메모 저장 |
| `/ajax/ajax_gisa_schedule_summary_list.asp` | 날짜 셀 클릭 | `schfrm` 전체 직렬화 + `sigongExpDate` | `.calR` 채움 |
| `/ajax/ajax_schedule_summary_view.asp` | 목록 항목 클릭 | `idx` | `#viewAreaPop` 채움 |

`schedule_summary_list(date, excelYN)` — 2번째 인자 `excelYN` 은 **받기만 하고 사용 안 함**
(엑셀 출력이 계획됐다가 빠진 흔적. 호출부는 전부 `''`)

## 2.4 문제점

| # | 심각도 | 내용 |
|---|---|---|
| B1 | 높음 | `setSchMemos()` 가 `$this.data('agency')` 를 읽지만 **textarea에 `data-agency` 속성이 없음** → 항상 `undefined` 전송. 지점별 메모 분리가 되지 않음 (숨은 `#AGENCY_MEMOS` 필드도 채워지지 않음) |
| B2 | 중간 | 메모 저장이 keyup 750ms 디바운스 + blur 로 **이중 호출**. 타이핑 중 계속 서버 요청 |
| B3 | 중간 | `.calR` 위치가 CSS(`position:absolute; left:80%`)와 인라인(`position:fixed; left:41%`) 로 **이중 지정** — 인라인이 이김. 창 크기에 따라 겹침 |
| B4 | 낮음 | `showmap()`, `showmap_hide()`, `liti_link()`, `SUB_GUBUN_CHG()` = **법무 시스템 잔재**. `liti_link()` 는 존재하지 않는 `?act=view&LITI_SEQ=` 로 이동 |
| B5 | 낮음 | 달력이 `<td>` 미닫음(`<td bgcolor=ffffff width="%">&nbsp;`) + `width="%"` 잘못된 값 — ASP 문자열 조립 오류 |
| B6 | 낮음 | `excelYN` 인자 미사용 |
| B7 | 낮음 | 지점 select에 `selected` 표시 로직 없음 — 검색 후 선택값이 유지되지 않음 |

## 3.3 문제점
| # | 내용 |
|---|---|
| C1 | select `onchange="fnSearch()"` 인데 `fnSearch()` 정의가 **폼 아래쪽 `<script>`**. 사용자 조작 시점엔 이미 로드돼 문제없지만 순서상 취약 |

## 4.2 목록 컬럼
번호 · 지점 · 접수형태 · 구분(결제방법) · 결제일 · 작성일 · 결제자명 · 결제금액 · 결제구분 · 승인번호 · 카드명/은행명 · 카드번호 · 비고 · 연락처 · 고객명 · 아파트명(+동호수 연결)

- 아파트명 컬럼은 `{아파트명}{동}-{호}` 를 **공백 없이 붙여서** 출력
- 연락처가 2개면 `<br>` 로 줄바꿈
- `카드번호` 컬럼은 존재하나 현재 데이터 전부 비어 있음
- 계좌이체 시 `카드명/은행명` 자리에 내부 계좌 별칭 사용 (예: `나마14`, `호감81`, `우리97`)
- 비고에 `M/D 자진발급`, `M/D 고객발급`, `M/D 취소`, `~ 링크결제` 같은 **수기 규칙** 존재

## 4.3 결제 취소 업무 흐름 (화면 안내문 기준)
```
1) 결제취소·수정 → 외부 payjoa 가맹점 페이지에서 처리
2) 그 후 반드시:
   계약관리 → 계약서 선택 → 시공관리 → 하단 '상세시공' 클릭
   → view 페이지 하단 '매출취소등록' 으로 취소금액 등록
```
> 즉 **PG 취소와 시스템 매출취소가 자동 연동되지 않고 수기 2단계**임.
> 안내문에 `'매출취소등록''` 따옴표 오타 있음.

## 4.4 매출취소 데이터의 위치
- 결제구분 `매출취소` 행은 `구분(결제방법)`, `승인번호`, `카드명` 이 전부 비어 있음
- 즉 **입금 테이블에 같이 쌓이되 결제수단 정보 없는 별도 종류**로 저장됨
- 입금등록 폼(`ChargingGubun`, §00 §4)에는 `매출취소` 선택지가 **없음** → 다른 경로(시공 view의 '매출취소등록')로만 생성

## 4.5 문제점
| # | 심각도 | 내용 |
|---|---|---|
| D1 | 중간 | 모든 행 `data-url=""` → 클릭 핸들러는 붙지만 아무 일도 안 일어남. **결제건에서 계약으로 이동 불가** |

## 5.4 반복되는 시스템 전역 패턴
1. **검색 select에 `selected` 유지 로직이 전 페이지에서 누락** — 검색 후 필터가 초기화된 것처럼 보임
2. **법무(liti) 시스템 잔재**가 계약관리·일정관리·결제내역 3곳에 산재
3. **ASP 값이 JS 문자열 리터럴에 직접 삽입** — 따옴표 이스케이프 없음
4. 목록에서 상세로 가는 링크가 페이지마다 제각각 (`data-url` / `onclick` / `<a>`)
5. 죽은 코드(주석 처리된 구버전 UI + 살아있는 핸들러) 가 파일마다 절반 가까이 차지
