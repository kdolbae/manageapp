# 1. 핵심 구조 — 양면 미끼 + ERP 수익화

| 면 | 미끼(무료) | 수익 |
|---|---|---|
| **소비자(B2C)** | 예산 책정 · 시공 순서 · 입주 일정 짜기 | (무료 — 유입 깔때기) |
| **협력업체(B2B)** | 계약관리 · 시공관리 | ERP(경비·통계·정산·분석) 유료, 리드/결제 수수료 |

이 구조에 대한 내 판단: **맞다. 그리고 두 미끼가 서로를 강화한다.**

---

# 2. 진짜 핵심 — 두 미끼가 연결된다 ★★

가장 큰 통찰: **소비자의 입주 플랜이 곧 협력업체의 리드(예약)다.**

```
소비자가 "예산+순서+일정" 플랜을 짜는 순간
  = 어떤 품목을(코팅·청소·줄눈…) 어느 현장에서 언제 살지 의향을 표명
  = 협력업체에게는 극도로 정제된 리드
```

### 플라이휠
```
소비자 무료 플래너 → 정제된 리드 발생
        ↓                    ↑
협력업체 유입 ← 리드 때문에 → 서비스 커버리지 ↑ → 플래너가 더 유용 → 소비자 ↑
```
- **계약관리는 사실상 이 거래를 잡는 CRM**이 된다.
- 미끼가 양쪽에서 서로를 당긴다 → 마켓플레이스 성립.

### 다리 개체 — "입주 플랜"
하나의 개체가 양면을 잇는다:
- 소비자: 내 체크리스트·타임라인
- 협력업체: 리드·예약요청
- 소비자가 일정 슬롯을 고르면 → **협력업체 시공 일정에 예약요청**으로 꽂힘 (기존 일정관리와 직결)

---

# 3. 소비자 미끼를 "진짜"로 만드는 설계

미끼가 장난감이면 안 온다. 셋 다 **이미 가진 자산으로** 강하게 만들 수 있다:

| 기능 | 구현 재료 | 비고 |
|---|---|---|
| **예산 책정** | 협력업체 **공개 단가(PriceBook, §05 B2)** 집계 | 평형·현장·needs 입력 → 품목별 예산 범위 |
| **시공 순서** | 나노마스터 도메인 지식 (베란다칠→줄눈→입주청소→새집증후군→나노코팅) | **범용 지식베이스**로 인코딩. 일반 도구엔 없는 전문성 |
| **입주 일정** | 입주일 역산 + 순서 + 품목별 리드타임 + 협력업체 가용일 | 슬롯 선택 → 예약요청 |

> 소비자 도구는 **예약/리드 엔진의 프론트엔드**다. 단가·일정·지식이 전부 재활용된다.

---

# 4. 수익화 — ERP 유료보다 큰 게 있을 수 있다

사용자 안(ERP 유료)은 견실. 여기에 층을 더 제안:

| 층 | 내용 | 규모감 |
|---|---|---|
| 1. Freemium SaaS | 계약/시공 무료, ERP·다지점·정산 유료 | 안정적, 예측가능 |
| 2. **리드/매칭 수수료** ★ | 소비자 의향 → 협력업체. 건당 or 성사당 | **마켓플레이스 본체 수익. ERP보다 클 수 있음** |
| 3. 결제 수수료 | 플랫폼 통한 결제에 소액 % | 결제 인프라 재사용 |
| 4. 마케팅 tier | 후기 연동·마이크로사이트 고급 | §6과 연결 |
| 5. 캠페인 SaaS | 주관사에게 박람회 운영 도구 | 기존 관계 활용 |

> ERP를 미끼 위 부가로 파는 건 좋다. 다만 **장기 수익의 무게중심은 리드/거래 수수료**일 가능성.

---

# 5. ★ 순서의 역설 — 미끼가 먼저 만들 대상이 아니다

전략적 미끼(소비자 도구) ≠ 먼저 만들 것.

```
소비자 도구는 "단가·후기·가용일"이 있어야 작동한다.
그 셋은 협력업체가 계약·시공·완료를 굴려야 생긴다.
→ 엔진(협력업체 운영)을 먼저 돌려 연료(단가·후기·가용일)를 만들고
   그다음 미끼(소비자 도구)에 불을 붙인다.
```
- 다행히 협력업체 운영(계약/시공)은 **이미 검증된 현행 기능** = M1~M2.
- 소비자 도구는 **완전 신규 UX** = 가장 새롭고 리스크 큰 부분 → 엔진 위에 올린다.
- 결론: **전략은 소비자, 건설 순서는 협력업체 먼저.**

# 6. 후기 → 인스타/블로그 연동 & "충성도 떨어지나?" ★★

## 6.1 결론: 떨어지지 않는다. 초기엔 오히려 성장 엔진.

**왜 leak이 성장인가**
- 초기 집대리엔 **관객이 없다.** 인스타·블로그·**네이버**엔 이미 관객이 있다.
- 후기를 그쪽으로 내보내면 = **무료 유통 + 역링크 + 인지도** → 사람이 집대리로 **되돌아온다.**
- 즉 "새어나가는 것"이 **부트스트랩 엔진**이다.

**핵심 조건: 항상 역링크/귀속을 심는다**
- 내보낸 인스타/블로그 글에 **집대리(또는 협력업체의 집대리 마이크로사이트) 링크·언급**을 항상 포함.
- 그러면 유출 = **유입 깔때기**로 뒤집힌다.

## 6.2 협력업체 충성도는 오히려 ↑
- 협력업체가 집대리를 쓰는 이유는 **운영(계약/시공/정산)** 때문. 후기 연동은 **보너스**다.
- 연동은 집대리가 **동력을 제공**한다(후기는 집대리 시공완료 플로우에서 수집). 떠나면 소스를 잃는다.
- 플랫폼 충성도의 진짜 원천은 ① 데이터·이력 잠김 ② 소비자 리드(네트워크효과) ③ 일상 워크플로 잠김.
  후기 연동은 이 셋을 전혀 위협하지 않고 **마케팅 효용만 더한다.**

## 6.3 딱 하나의 함정
- **"후기를 인스타에 올려줌"이 유일한 가치면** → 충성도 낮다(더 싼 소셜툴로 대체됨).
- 그래서 연동은 **운영 코어 위의 부가 tier**로. 전체 가치 제안으로 삼지 말 것.

## 6.4 설계 원칙
- **원본은 집대리에 남기고, 복사본을 내보낸다.** (소비자 신뢰용 인앱 사회적증거 + 협력업체 마케팅, 둘 다)
- **동의 내장**: 후기 작성 시 채널별 공개 동의 수집 (개인정보·저작권·초상). 사용자가 이미 언급한 부분 — 맞다.
- **원클릭 콘텐츠 생성**: before/after 사진 + 후기 + 브랜드 템플릿 → 인스타/블로그 즉시 게시용. 협력업체 수고 최소화 = 사용률 ↑.
- **네이버 우선**: 국내 입주/시공 탐색은 인스타보다 **네이버 블로그·플레이스**가 더 큼. 여기 연동을 1순위로.

# 7. 정직한 리스크 (파트너로서의 경고)

| 리스크 | 완화 |
|---|---|
| 양면 마켓 콜드스타트(닭-달걀) | **박람회/현장을 교두보로.** 한 현장에 소비자·협력업체가 이미 공존 |
| 소비자 도구가 협력업체 없이도 유용해야 함 | 순서·예산 지식은 **협력업체 없이도** 가치(정보성) |
| 소비자 도구 = 신규 UX 리스크 | 엔진(협력업체) 먼저, 소비자는 저비용 실험으로 검증 |
| 리드 수수료 = 협력업체 저항 가능 | 초기엔 무료 리드로 락인 후 유료화 |

# 8. 한 문장 요약
> **협력업체 운영(무료 미끼)으로 엔진을 돌려 단가·후기·가용일을 만들고,
> 그 연료로 소비자 입주 플래너(미끼)를 돌려 리드를 만들고,
> 후기는 네이버·인스타로 내보내(역링크로) 양쪽을 부트스트랩한다.
> 수익은 ERP 부가 + 리드/결제 수수료.**
