# 집대리 — 결제 정산 · 수수료 · AS/배상 구조

> 2026-07-23 확정 사항. [11](11_컨설턴트양성_이탈방지.md) 상위. ※ 기획/전략 + 규제 플래그.

---

# 1. 집대리 = 결제 수취 + 정산 (마켓플레이스 세틀먼트)

```
소비자 결제 → 집대리 수취 → (수수료 차감) → 파트너에게 지급
```
- 모든 결제가 플랫폼 경유 → **이탈방지(§11 L2)·신뢰의 핵심**. 방향 좋음.
- 필요: 업체별 **수수료 룰** + **정산(payout)** 엔진.

## 1.1 ⚠️⚠️ 규제 현실 — 반드시 확인 (가장 중요)
"플랫폼이 남의 돈을 받아서 나눠준다" = **규제 영역**이다. 모르고 만들면 위험.

| 법 | 쟁점 | 대응 |
|---|---|---|
| **전자금융거래법** | 제3자 결제대금 수취·정산 = **전자지급결제대행(PG)/결제대금예치(에스크로)** 영역. 직접 하면 등록·라이선스 필요 | ★ **정산을 대신 해주는 PG/에스크로를 쓴다.** 라이선스 있는 곳이 자금을 쥐고, 집대리는 "분할정산/하위가맹점"만 지시 |
| **전자상거래법** | 소비자·판매자 중개 = **통신판매중개업 신고** + 중개자 지위·책임 고지 의무 | 신고(비교적 가벼움) + 약관에 명시 |
| 정산 투명성 | 파트너에게 정산내역·주기 공개 | 정산 명세 자동화 |

> **결론: 집대리가 스스로 "전자금융업자"가 되지 않도록,
> 마켓플레이스 정산(분할정산/정산대행)을 지원하는 PG를 고른다.**
> → 이건 [06] PG선택(Q13)에 **새 필수조건**을 추가: "**정산대행/분할정산 지원**".
> → 세부는 전자금융·전자상거래 **법무 전문가 확인 필수** (개발 전).

# 2. 수수료 룰 엔진 — "모든 옵션 가능" ★

사용자 요구: 업체별/품목별, 정액/비율, 다 되게. → **하드코딩 말고 룰 테이블.**

```
CommissionRule
  scope: global | partner | item_category | product | campaign
  target_id     (해당 파트너/품목/캠페인)
  type: fixed(정액) | percent(비율)
  value
  effectiveFrom, effectiveTo   (기간별 변경, 이력 보존)
  priority (구체적일수록 우선)
```

## 2.1 우선순위 (가장 구체적인 것이 이김)
```
상품(product) > 품목(item_category) > 파트너(partner) > 전역기본(global)
```
- 예: "A업체 코팅은 5%, A업체 기본은 3만원, 전역기본 3%" → 코팅엔 5% 적용.
- **기간별 이력** 보존(§07-10) → 언제 요율 바꿨는지 다 남음.

## 2.2 정산 원장 흐름 (§05 원장 D1 확장)
```
PAYMENT_IN   소비자→집대리 (총액)
  ├ COMMISSION  집대리 수익 (룰 계산)
  └ PAYABLE     파트너 지급예정
PAYOUT       집대리→파트너 (정산 실행)  ← 정산주기 배치
```
- 한 결제가 **수수료 + 파트너몫**으로 자동 분개 → 어긋날 수 없음.
- 파트너 정산명세·집대리 수익(수수료)이 **같은 원장**에서 나옴 → 사업분석(§07-10) 직결.

# 3. AS / 배상 책임 — 단계화

사용자 방침:
| 시점 | 정책 |
|---|---|
| **도입기** | 보험 없음. **1차 책임 = 업체 또는 개인 시공기사** |
| **성숙기** | 파트너에게 **배상책임보험 의무화** |
| 후기 AS(중대·배상) | **배상책임보험**으로 커버 |

## 3.1 책임 2단계
- **운영 AS(1차)**: 하자보수 = 파트너/기사가 **직접 이행**(비용 부담). 10년 A/S 약관의 의무.
- **배상책임(중대)**: 재산·인적 피해 등 = **배상책임보험**(성숙기 의무).

## 3.2 집대리 포지셔닝 — 초기엔 조심 ★
- **초기(보험 전)**: 집대리는 AS를 **중개·추적·독촉**만. **"집대리가 물어준다"고 강하게 보증하지 말 것** → 무보험 배상 리스크를 플랫폼이 떠안게 됨.
  - 소비자 문구: "담당 매니저가 AS를 **책임지고 관리**" (이행 주체는 파트너).
- **성숙기(보험 후)**: 파트너 보험을 근거로 **집대리 보증을 강하게** 내세울 수 있음 → §11 "AS=리쉬" 완성.

## 3.3 시스템이 남길 것
```
Partner.insurance   (보험사·증권번호·보장범위·만기)   ← 성숙기 필수
WorkOrder.liableParty  (업체 or 개인기사)            ← 1차 책임 주체 기록
ASClaim  (접수·귀속 파트너·처리·보험청구 여부·상태)
```
- 성숙기: **유효 보험 없으면 리드 배정 제한** 같은 강제 옵션 가능.

## 3.4 아이디어 — 단체 배상책임보험
- 집대리가 **파트너 단체보험**을 협상(프랜차이즈 방식):
  - 파트너: 개별 가입보다 싸고 표준화 → 가입 유인.
  - 집대리: 보장범위 **통제** + "모든 파트너 배상책임보험 가입" = **소비자 신뢰 배지** + 품질 필터(부실 파트너 걸러짐).
  - 설계사형 조직 DNA와도 맞음(보험 취급 역량).
- 성숙기 도입. 초기엔 불필요.

# 4. 종합
```
소비자 결제 → [집대리 수취: PG 정산대행 경유] → 수수료 룰 분개 → 파트너 정산
                                              └ 집대리 수익 원장
AS: 초기 = 파트너 1차책임(집대리는 관리·추적)
    성숙 = 배상책임보험 의무 → 집대리 보증 강화(리쉬 완성) + 단체보험(신뢰배지)
```
