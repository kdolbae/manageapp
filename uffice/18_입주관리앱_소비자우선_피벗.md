# 집대리 — 입주관리 앱 우선 (소비자 단독 도구로 시작)

> 2026-07-23 컨셉 피벗. [09](09_제품전략_양면플랫폼.md)·[16](16_페이지구성_섹터계획.md)·[17](17_실행계획_한달스프린트.md) 재정렬.

---

# 1. 피벗 — 첫 제품은 소비자 "입주 관리 앱"

컨시어지 마켓플레이스를 먼저 만드는 대신, **입주하는 사람을 위한 개인 입주 관리 도구**로 시작한다.
- 내 입주 일정·시공 일정 기록
- 업체·연락처 저장 + **탭 투 콜**(바로 전화)
- 수기 견적서 **사진 찍어** 업체별로 정리
- 시공 전후 사진 앨범
- 입주 준비 체크리스트 + 준비물
- 각 시공(청소·줄눈·코팅…) **공통 설명·순서** (지식)
- → "입주 준비를 미리, 한 곳에서" 관리

---

# 2. 왜 이게 더 나은 시작인가 — 콜드스타트 해결 ★★

이전 고민(§09-5 "순서의 역설": 소비자 도구는 공급[단가·업체·가용일]이 있어야 작동)이 **여기서 사라진다.**

```
입주 관리 앱은 공급이 0이어도 유용하다.
  = 소비자가 "자기가 직접 구한 업체·견적"을 정리하는 개인 도구.
  = 플랫폼에 협력업체가 한 곳도 없어도 혼자 쓸 수 있다.
```
- **단독 유용(single-player utility)** → 공급 없이 소비자 확보 가능.
- 고관여 순간(입주)에 사람을 **먼저** 잡는다. 마켓은 그 위에 얹는다.
- 이것이 **"도구로 와서 네트워크로 남는다"** 정석 콜드스타트.

# 3. MVP = 입주 관리 앱 (소비자, 무료, 단독)

| # | 화면 | 내용 |
|---|---|---|
| 1 | 홈 대시보드 | 입주 D-day, 다음 일정, 미완료 체크 |
| 2 | 입주 프로필 | 집(현장)·입주예정일 |
| 3 | 입주 타임라인 | 입주 전후 할 일(역산) |
| 4 | 시공 일정 | 각 시공 예정일 기록 |
| 5 | 업체·연락처 | 업체 등록·연락처·**탭 투 콜** |
| 6 | 견적 보관함 | 수기 견적서 **사진**+금액 메모, 업체별 |
| 7 | 시공 전후 사진 | 시공별 before/after 앨범 |
| 8 | 체크리스트 | 준비물·할일 (기본 템플릿+커스텀) |
| 9 | 시공 설명(공통) | 각 시공 뭐냐·순서·준비물 (지식베이스) |

→ 백엔드 공급·결제·매니저 **불필요**. 빠르고 리스크 작고 **진짜 유용**.
→ [16] S1(컨시어지)보다 **더 앞선 S0.5** 성격. 실질 MVP는 이것.

# 4. 데이터가 곧 마켓 연료

소비자가 입력하는 모든 게 나중 마켓 가치가 된다:
| 앱 데이터 | 나중 쓰임 |
|---|---|
| 등록한 업체·연락처 | 협력업체 디렉터리의 씨앗 |
| 견적서(사진·금액) | 구매의향 = **리드**, 단가 데이터 |
| 시공 일정·현장 | 매칭·가용일 |
| 전후 사진·후기 | 마케팅 콘텐츠·사회적 증거 |

---

# 5. 성장 단계 (사용자 표현대로)

```
1) 입주 관리 앱으로 고객 확보          [소비자 단독 도구]
2) 시공상품·기사(업체) 붙이기          [공급 얹기 → 마켓]
3) 기사·업체 계약관리 프로그램 붙이기   [B2B ERP = 현행 UFFICE 대체]
4) 수익화                              [리드/수수료·구독]
```
- 기존 섹터(S1~S5)는 유지하되, **맨 앞에 "입주 관리 앱(단독)"** 을 둔다.

---

# 6. 정직한 특성 — 일회성 고관여

- 입주는 **일회성 이벤트** → 몇 주 집중 사용 후 이탈(리텐션 낮음). 정상이다.
- 따라서 **활성 창(active window) 안에** 가치를 뽑아야:
  - 창 안에서 **리드·거래·후기·추천**을 만든다.
  - 성장은 리텐션이 아니라 **새 입주자 유입 + 추천**으로.
- (이사·웨딩 앱과 같은 episodic 구조. 나쁜 게 아니라 설계 전제.)
