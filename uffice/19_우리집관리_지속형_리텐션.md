# 집대리 — 우리집 관리 (일회성 → 지속형 리텐션)

> 2026-07-23 확장. [18](18_입주관리앱_소비자우선_피벗.md) 상위. 일회성 문제(§18-6)의 해법.

---

# 1. 확장 — "집(Home)"을 영속 루트 객체로

입주 관리 앱을 **집 자체의 영구 기록장**으로 키운다.
- 입주 = 끝나는 이벤트가 아니라 **집 타임라인의 첫 장면**.
- 집을 루트로 두면, 입주 후에도 계속 쌓이고 → **리텐션 해결.**

---

# 2. 3층 구조 — wedge → retention → 수익화

```
① 입주 (wedge)        고관여 순간에 사람을 잡는다        [일회성, 유입]
② 우리집 관리 (retention)  집의 영구 기록·상시 관리         [지속, 붙잡음]
③ 마켓 (수익화)        재시공·AS·신규니즈를 거래로         [수년에 걸친 재거래]
```
- ①이 데려오고, ②가 붙잡고, ③이 번다.

---

# 3. 지속 관리 기능 (입주 후에도 쌓이는 것)

| 영역 | 내용 |
|---|---|
| **시공 이력** | 언제·무엇을·**누구에게** 시공받았나 (집의 이력카드) |
| **계약·업체 기록** | 누구와 계약, 업체·연락처·견적서(사진) |
| **지출·이체 내역** | 집 관련 결제·이체 기록 |
| **보증·AS 알림** ★ | 각 시공 보증 만료일 추적 → 알림 ("코팅 A/S ~2036") |
| **관리비** | 월 관리비 기록·조회 (아파트아이류 흡수) |
| **대출 정보** | 주담대·이자·상환 일정 |
| **집 문서함** | 계약서·보증서·영수증·설명서 보관 |
| **정기 리마인더** | 필터 교체·보일러 점검·정수기 등 |
| **집 메모** | 집과 관련해 기억할 것들 |

---

# 4. ★ 관리비 = 월간 리텐션 앵커

- 리텐션의 핵심은 **"매달 열 이유"**. 그게 **관리비**다(아파트아이가 사는 이유).
- 관리비 + 보증알림 + 집기록 → **매달 앱을 연다.**
- ⚠️ 단, 관리비 **자동 조회는 통합 난이도 있음**(관리사무소/K-apt 연동).
  - 초기: **수기 입력·영수증 사진**.
  - 이후: 연동(외부 의존, PG·알림톡처럼 별도 시간표).

---

# 5. ★ 보증·AS 알림 = 재거래 엔진

- 10년 A/S(§12)를 **추적**하면, 수년 뒤 "보증 만료 임박 → 재시공?" = **리드**.
- 일회성 시공이 **10년에 걸친 재판매**로 바뀜.
- §11 "AS=리쉬"가 여기서 **리텐션 + 재수익화**로 완성.

---

# 6. 주관사도 사용자 (B2B 채널)

- 주관사(박람회 주최)도 사용 대상 → **§08 캠페인·멀티테넌트 모델**에 이미 들어맞음.
- 주관사의 박람회가 **입주자를 앱으로 유입**시키는 채널이 됨(유입 ↔ B2B 양쪽).
- 주관사 = 또 하나의 테넌트/파트너 유형.

---

# 7. 데이터 모델 함의 — Home이 루트

```
Home (집)  ← 영속 루트
 ├─ 입주 이벤트(입주일·타임라인)     [①]
 ├─ 시공 이력(업체·계약·견적·전후사진·보증) [②]
 ├─ 지출·이체
 ├─ 관리비 / 대출
 ├─ 문서함 · 리마인더 · 메모
 └─ (연결) 마켓 리드·계약           [③]
```
- 사용자 1명이 **집 N개**(이사 시 새 집 추가, 과거 집 보관) 가질 수 있게.

---

# 8. 스코프 규율 (중요)
- **MVP는 여전히 입주 organizer(§18 9화면)로 시작.** 다 만들려 하지 말 것.
- 단, **Home을 루트 객체로** 설계 → 관리비·대출·보증알림 등을 **나중에 얹어도 리팩터 없이** 붙는 구조.
- 관리비 자동연동·대출연동은 **후순위**(외부 통합). 초기엔 수기·사진.

---

# 9. 다음 스텝
1. MVP(§18) = 입주 organizer, 단 **Home 루트 스키마**로.
2. 리텐션 2차: 보증·AS 알림 → 관리비(수기) → 리마인더.
3. 마켓 3차: 재시공 리드 → 업체·기사 → 계약관리.
