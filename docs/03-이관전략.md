# UPIS → 신규 시스템 이관 전략

- 문서 버전: v0.1
- 관련: [`scripts/ingest-upis.ts`](../scripts/ingest-upis.ts) (스켈레톤)

## 1. 원칙

1. **손실 없는 원본 보존**: 먼저 UPIS 원본을 Bronze(`stg`)에 형변환 없이 적재한다.
2. **멱등(재실행 안전)**: 같은 배치를 다시 돌려도 중복이 생기지 않는다
   (`(sourceSystem, sourcePk)` 유니크).
3. **대사(Reconciliation) 필수**: 이관 후 행수·금액 합계를 원본과 대조해 성공을 판정한다.
4. **단계 분리**: 추출(Extract) → 적재(Load, Bronze) → 표준화(Transform, Silver) → 자산화(Gold).

## 2. 추출(Extract) — 세 가지 확보 경로

확정된 방식에 맞춰 스크립트 입력 어댑터만 교체한다.

| 경로 | 방법 | 적합 상황 |
| --- | --- | --- |
| A. SQL 덤프 | `mysqldump`/`pg_dump` → 복원 후 조회 | 스냅샷 이관 (권장 시작점) |
| B. 직접 접속 | 운영 DB read-only 계정으로 조회 | 최신 상태 필요 시 |
| C. CSV/엑셀 | 내보내기 파일 파싱 | DB 접근 불가 시 |

> 어떤 경로든 결과는 동일하게 `StgRecord`(원본 1행 = JSONB)로 적재된다.

## 3. 적재(Load) — Bronze

```
for each 원본테이블 T:
    batch = StgBatch(sourceObject=T, status=RUNNING)
    for each row in T:
        StgRecord(batchId=batch.id, sourceObject=T,
                  sourcePk=row.PK, payload=row_as_json)
    batch.rowCount = n; batch.status = SUCCEEDED
```

## 4. 표준화(Transform) — Silver

`StgRecord.payload`를 표준 엔터티로 매핑한다. **매핑 규칙은 UPIS 스키마 확보 후 확정.**

```
upis.거래처   → core.Party      (+ sourceSystem/sourcePk 기록)
upis.계약     → core.Contract
upis.계약품목 → core.ContractItem
upis.정산     → core.Settlement
...
```

- `upsert`로 `(sourceSystem, sourcePk)` 기준 멱등 반영.
- 코드값(상태·유형)은 **매핑표**를 통해 표준 enum으로 변환.

## 5. 자산화(Gold) — 카탈로그 등록

표준화된 데이터셋을 `DataAsset`으로 등록하고:

- `DataAssetField`에 데이터 사전(필드·타입·PII 여부) 기록
- `DataLineage`에 `UPIS.<원본테이블> → 변환 → core.<엔터티>` 계보 기록
- `DataQualityCheck`로 완전성/유효성/유일성/정합성/적시성 검증 등록 및 통과율 저장

기본 카탈로그 시드는 [`prisma/seed.ts`](../prisma/seed.ts) 참고.

## 6. 대사(Reconciliation) 리포트

| 검증 | 기준 |
| --- | --- |
| 행수 일치 | `count(UPIS.T) == count(stg where sourceObject=T)` |
| 표준화 반영 | `count(stg) == count(core) + 정당한 제외건` |
| 금액 합계 | `sum(UPIS 금액) == sum(core 금액)` (허용오차 0) |
| 유일성 | `sourcePk` 중복 0건 |
| 필수값 | 표준 필수 컬럼 NULL 0건 |

결과는 `DataQualityCheck`에 dimension별로 기록되어 자산 카탈로그에서 확인 가능.

## 7. 개인정보/보안

- `regNo` 등 민감항목은 `DataAssetField.isPii=true`로 표시하고 접근·조회 시 마스킹.
- 이관 로그·덤프 파일은 처리 후 안전 폐기, 보존기간 정책 준수.
- 접속 정보/자격증명은 저장소에 커밋하지 않는다(`.env`, 시크릿 매니저 사용).

## 8. 실행 순서 (DB 확보 후)

```bash
npx prisma migrate dev        # 스키마 생성
npx tsx scripts/ingest-upis.ts --source dump --path ./upis_dump   # Extract+Load
npx tsx scripts/transform.ts  # Bronze → Silver (스키마 확정 후 구현)
npx tsx prisma/seed.ts        # 자산 카탈로그 시드
```
