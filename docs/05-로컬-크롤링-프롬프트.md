# 로컬 실행용 프롬프트 — uffice(UPIS) 화면 구조 취합

클라우드 세션은 `nm00.uffice.kr` 접속이 차단되어 있으므로, **본인 PC의 Claude Code**에서
아래 프롬프트를 그대로 붙여넣어 실행합니다. 결과(구조 문서)는 이 브랜치에 푸시됩니다.

## 사전 준비 (1분)

```bash
git clone https://github.com/kdolbae/jipdarie.git && cd jipdarie
git checkout claude/upis-contract-management-info-ewsq1o
claude            # 로컬 Claude Code 실행
```

`.env`는 프롬프트 안에서 만들도록 되어 있습니다(커밋되지 않음). 비밀번호는 프롬프트에
직접 적지 말고, 아래 `<...>` 자리에 실행 시점에만 채워 넣으세요.

## 프롬프트 (아래 전체를 복사해서 붙여넣기)

```
너는 이 저장소(집대리)에서 UPIS(uffice) 사이트의 화면 구조를 "읽기 전용"으로 취합하는 작업을 맡는다.
목표: https://nm00.uffice.kr 에 로그인해 모든 메뉴/화면을 돌면서 각 화면의 목록 컬럼·입력 폼 필드·버튼·메뉴 구조를 수집하고,
그 결과를 prisma/schema.prisma 의 DB 설계와 대조해 부족한 테이블/필드를 찾아내는 것이다. 데이터(행 값)는 수집하지 않는다.

## 절대 규칙 (안전)
- 읽기 전용. 로그인 폼 외에는 어떤 폼도 제출하지 말고, 저장/삭제/승인/전송/발송/다운로드 버튼은 절대 누르지 마라.
- confirm/alert 창은 항상 취소한다. 링크는 GET 이동만 허용한다.
- 자격증명은 .env 에만 둔다. 코드·문서·커밋·로그에 절대 남기지 마라. 스크린샷(data/)도 커밋하지 마라.
- 서버에 부담을 주지 않도록 페이지 간 0.7초 이상 간격을 둔다.

## 1단계: 환경 준비
1. `npm install` 실행.
2. 로컬에는 사전 설치 Chromium이 없으므로 `npx playwright install chromium` 실행.
3. 프로젝트 루트에 .env 파일을 만들고 아래 3줄을 넣어라 (값은 내가 채운 것을 그대로 사용):
   UFFICE_BASE_URL="https://nm00.uffice.kr"
   UFFICE_USER="<아이디>"
   UFFICE_PASS="<비밀번호>"
4. `git check-ignore .env` 로 .env 가 gitignore 대상인지 확인해라.

## 2단계: 로그인 확인 및 크롤러 보정
1. `npm run crawl:uffice -- --max 5` 로 짧게 실행해 로그인이 되는지 확인해라.
2. 로그인이 실패하면 data/uffice-shots/login-failed.png 를 보고 scripts/crawl-uffice.ts 의 login() 을 실제 로그인 폼에 맞게 고쳐라
   (로그인 경로가 루트가 아니거나, 아이디 입력란 선택자가 다르거나, iframe 안에 있거나, 로그인 버튼 클릭이 필요한 경우 등).
3. 로그인 후 첫 화면의 메뉴가 JS로 그려지거나 iframe/frameset 구조라면, 크롤러가 메뉴를 놓치지 않도록 extract() 와 링크 수집 로직을 보정해라.
   (onclick 으로 이동하는 메뉴, 좌측 트리 메뉴, 탭 메뉴, 팝업 링크 등을 모두 GET URL 로 환원해서 큐에 넣는다.)
4. DENY 정규식이 정상 조회 메뉴까지 막고 있으면(예: URL 에 'update' 가 들어가는 단순 조회 화면), 해당 패턴을 완화하되 실제 쓰기 동작 URL 은 계속 차단해라.

## 3단계: 전체 수집
1. `npm run crawl:uffice -- --max 400 --delay 800` 으로 전체 화면을 수집해라.
2. 산출물 docs/uffice-structure.generated.md 와 .json 을 열어 확인하고,
   메뉴 목록과 대조해 빠진 화면이 있으면 그 URL 을 직접 큐에 추가해 다시 수집해라.
3. 목록 화면은 "컬럼 헤더"가, 등록/수정 화면은 "폼 필드(라벨/name/type/select 옵션)"가 빠짐없이 잡혔는지 점검해라.
   상세 화면이 팝업(window.open)이면 그 URL 도 직접 방문해 수집해라.

## 4단계: 정리 문서 작성
docs/06-UPIS-화면구조-정리.md 를 작성해라. 내용:
1. 메뉴 트리 (대메뉴 > 중메뉴 > 화면) 전체.
2. 화면별 요약: 화면명, URL, 성격(목록/등록/상세/통계), 목록 컬럼, 입력 필드(select 옵션 = 코드값 후보), 주요 버튼.
3. 화면에서 드러난 "엔터티" 목록과 각 엔터티의 필드 후보 (동일 개념은 하나로 합쳐라).
4. 코드값 목록 (select 옵션에서 뽑은 상태/유형/구분 값들).

## 5단계: DB 설계 대조 (갭 분석)
prisma/schema.prisma 와 docs/02-데이터모델.md 를 읽고, docs/07-UPIS-DB매핑-갭분석.md 를 작성해라. 내용:
1. UPIS 엔터티/필드 → 현재 스키마의 모델/필드 매핑표 (일치 / 이름만 다름 / 없음).
2. 현재 스키마에 "없는" 테이블·필드·코드값 목록 (추가 필요).
3. 현재 스키마에 있지만 UPIS 에는 없는 항목 (유지 or 삭제 판단 근거와 함께).
4. 추가가 필요한 항목은 prisma/schema.prisma 에 실제로 반영해라 (기존 모델·필드는 삭제/변경하지 말고 추가만).
   반영 후 `npx prisma validate`, `npx prisma generate`, `npx tsc --noEmit` 이 모두 통과해야 한다.

## 6단계: 커밋·푸시
- 커밋 대상: docs/06-*, docs/07-*, docs/uffice-structure.generated.{md,json}, prisma/schema.prisma, 크롤러 수정분.
- 커밋 금지: .env, data/ 의 스크린샷, 개인정보가 포함된 어떤 파일.
- 커밋 전에 산출물에 사용자 이름/전화/사업자번호 같은 실제 데이터 값이 섞여 있는지 grep 으로 확인하고, 있으면 제거해라.
- 브랜치 claude/upis-contract-management-info-ewsq1o 에 푸시해라.
```
